# Visual Quality Checklist

Use this checklist before reporting completion. Mark items as pass, fail, or not applicable; do not claim a pass without checking.

## Product and UX
- [ ] The page's purpose is clear quickly.
- [ ] The primary action is obvious and works.
- [ ] Navigation labels and destinations are understandable.
- [ ] Content order supports the user's task.
- [ ] Empty, loading, error, and success states are handled where relevant.
- [ ] No visible control is dead or misleading.

## Visual system
- [ ] Typography has a clear hierarchy.
- [ ] Spacing and alignment are consistent.
- [ ] Color roles are consistent and readable.
- [ ] Components share coherent shapes and states.
- [ ] Content width and density suit the page.
- [ ] Decorative effects support rather than compete with content.
- [ ] Images are relevant, sized well, and cropped intentionally.

## Responsive
- [ ] Narrow phone layout is usable.
- [ ] Tablet layout is intentional.
- [ ] Desktop layout uses space effectively.
- [ ] No unintended horizontal overflow.
- [ ] Menus, dialogs, forms, and tables work at narrow widths.
- [ ] Sticky/fixed UI does not cover content.

## Accessibility
- [ ] Semantic elements are used appropriately.
- [ ] Form controls have labels.
- [ ] Icon-only controls have accessible names.
- [ ] Keyboard navigation works.
- [ ] Focus is visible.
- [ ] Contrast is adequate.
- [ ] Reduced-motion preference is respected.

## Engineering
- [ ] Existing functionality and integrations are preserved.
- [ ] No unnecessary dependency was added.
- [ ] Console/build/lint issues were checked where tools permit.
- [ ] Assets load and have appropriate alternatives.
- [ ] No fake data or unimplemented features are presented as real.
- [ ] Actual tests and limitations are accurately reported.

## Final notes
Record:
- routes/screens reviewed;
- viewport sizes reviewed;
- interactions exercised;
- commands/tests run;
- known defects or unverified areas.
